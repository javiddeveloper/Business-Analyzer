# 🤖 Coder Review

یک سرویس سبک و بدون وابستگی سنگین (فقط Node.js خالص) که به گیت‌لب وصل می‌شود، روی هر Merge Request به‌صورت خودکار ریویوی کد با هوش مصنوعی انجام می‌دهد و نتیجه را به شکل کامنت روی همان MR می‌گذارد.

این پروژه از معماری و تجربه‌ی [business-generator-light](../business-generator-light) الهام گرفته — همان الگوی «بدون دیتابیس، بدون فریم‌ورک سنگین، ذخیره‌سازی فایلی» و همان فیچر **پایگاه دانش** (استانداردهای تیم که در هر ریویو خودکار لحاظ می‌شود) — اما فقط همین یک کار را انجام می‌دهد: **ریویوی کد**. هیچ Product Owner، Auto-Runner یا نوشتن خودکار کد در این پروژه نیست.

## ✨ قابلیت‌ها
- **وب‌هوک گیت‌لب:** با باز شدن یا آپدیت‌شدن (کامیت جدید) هر Merge Request، خودکار فعال می‌شود.
- **ریویوی مبتنی بر Tech Lead:** پرامپت `roles/tech-lead.md` چک‌لیست ریویو (منطق، امنیت، کد مرده، پوشش تست، ...) را تعریف می‌کند.
- **پایگاه دانش:** از داشبورد استانداردهای پروژه‌ات را (نوشتن مستقیم، ویرایش، یا آپلود `.md`/`.txt`) ثبت کن؛ همه‌ی آن‌ها خودکار در هر ریویو به مدل داده می‌شود. متن کامل هر یادداشت در همان صفحه قابل باز کردن و خواندن است.
- **کامنت روی MR:** نتیجه (APPROVE ✅ یا REQUEST_CHANGES 🔴 + خلاصه + نکات فایل‌به‌فایل) مستقیم روی خود Merge Request در گیت‌لب گذاشته می‌شود.
- **داشبورد ریسپانسیو:** روی موبایل تک‌ستونه و روی دسکتاپ دو‌ستونه؛ وضعیت زنده‌ی اتصال گیت‌لب و مدل فعال در هدر، به‌همراه دکمه‌ی بروزرسانی لیست MRها.
- **تب جدا برای هر Merge Request:** هر MR باز، یک تب در همان صفحه دارد (با چراغ وضعیت). چند MR می‌توانند **هم‌زمان** ریویو شوند — هر تب وضعیت و نتیجه‌ی خودش را جدا نگه می‌دارد. فقط برای یک MR مشخص، دو ریویوی هم‌زمان اجرا نمی‌شود.
- **حالت ریویوی خودکار:** یک سوییچ در هدر؛ سرور هر چند ثانیه (پیش‌فرض ۱۲۰ ثانیه) MRهای باز را می‌بیند و هرکدام کامیت جدید داشته باشد را خودکار ریویو و کامنت می‌کند. برخلاف وب‌هوک، این حالت **نیازی ندارد سرور تو از سمت گیت‌لب قابل‌دسترسی باشد** — برای اجرای لوکال/پشت NAT همین کافی است.
- **پاسخ سریع به وب‌هوک:** درخواست گیت‌لب فوراً تأیید می‌شود و ریویوی واقعی در پس‌زمینه انجام می‌شود تا به Timeout وب‌هوک نخوریم.

## 🛠 نصب

```bash
npm install
cp secrets.env.example secrets.env
```

فایل `secrets.env` را باز کن و مقادیر زیر را پر کن:

1. **GITLAB_URL** — آدرس گیت‌لب (پیش‌فرض `https://gitlab.com`؛ برای نسخه‌ی self-hosted آدرس خودت را بگذار).
2. **GITLAB_TOKEN** — یک Access Token (Project یا Personal) با اسکوپ `api`.
3. **WEBHOOK_SECRET** — یک رشته‌ی دلخواه و تصادفی؛ همین مقدار باید موقع ساخت Webhook در گیت‌لب هم به‌عنوان Secret Token وارد شود.
4. **GITLAB_PROJECT_ID** *(اختیاری)* — اگر پر شود، داشبورد و ریویوی خودکار فقط MRهای همان پروژه را می‌بینند؛ خالی یعنی همه‌ی MRهای بازی که توکن دسترسی دارد.
5. **AI_PROVIDER / AI_MODEL / AI_API_KEY / AI_BASE_URL** — تنظیمات مدل هوش مصنوعی (پیش‌فرض یک اندپوینت سازگار با OpenAI مثل GapGPT؛ برای Gemini مقدار `AI_PROVIDER=gemini` و `GEMINI_API_KEY` را بگذار).

## 🚀 اجرا

```bash
npm start
```

سرور روی `http://localhost:8078` بالا می‌آید (با متغیر محیطی `PORT` قابل تغییر است).

## 🔗 تنظیم Webhook در گیت‌لب

در پروژه‌ی گیت‌لب: **Settings → Webhooks**
- **URL:** `http://<آدرس-سرور-تو>:8078/webhook/gitlab`
- **Secret Token:** همان مقدار `WEBHOOK_SECRET` در `secrets.env`
- **Trigger:** فقط تیک **Merge request events** را بزن.
- روی **Add webhook** کلیک کن.

> سرور باید از اینترنت (یا حداقل از شبکه‌ی گیت‌لب) قابل‌دسترسی باشد — اگر گیت‌لب self-hosted روی همان شبکه‌ی داخلی است، آدرس داخلی سرور کافی است؛ برای gitlab.com باید سرور را جایی با IP/دامنه‌ی عمومی اجرا کنی (یا از یک تانل مثل ngrok برای تست استفاده کنی).

## 🖥 داشبورد

به `http://localhost:8078/admin` برو:
- **هدر:** وضعیت اتصال گیت‌لب (سبز/قرمز به‌همراه نام کاربر توکن)، مدل فعال، سوییچ **ریویوی خودکار**، و دکمه‌ی **بروزرسانی**.
- **تب‌های MR:** هر Merge Request باز یک تب دارد؛ با کلیک روی تب، جزئیات (شاخه، نویسنده، کامیت فعلی) و دکمه‌ی «اجرای ریویو» را می‌بینی. اگر تیک «کامنت روی گیت‌لب ثبت شود» را برداری، نتیجه فقط در داشبورد نمایش داده می‌شود و بعداً با دکمه‌ی «💬 ثبت این نتیجه روی MR» می‌توانی آن را ارسال کنی.
- **اجرای هم‌زمان:** می‌توانی روی چند تب پشت‌سرهم «اجرای ریویو» بزنی؛ همه با هم پیش می‌روند و چراغ هر تب وضعیت خودش را نشان می‌دهد (آبی چشمک‌زن = در حال اجرا، سبز = APPROVE، قرمز = REQUEST_CHANGES، نارنجی = خطا).

## 📚 پایگاه دانش

در ستون کناری همان داشبورد است. اگر `ADMIN_TOKEN` را در `secrets.env` خالی گذاشته‌ای، فقط از همان دستگاه (localhost) بدون نیاز به توکن قابل دسترسی است — دقیقاً مثل محافظت شبکه‌ای business-generator. برای دسترسی از جای دیگر، یک `ADMIN_TOKEN` بگذار و همان را در پنل وارد کن.

## ⚠️ محدودیت‌های نسخه‌ی فعلی
- کامنت‌ها روی MR به‌صورت یک Note کلی گذاشته می‌شوند، نه به‌صورت کامنت خطی/inline روی دیف (که نیازمند محاسبه‌ی position schema گیت‌لب است) — نکات فایل‌به‌فایل داخل همان یک کامنت به شکل لیست می‌آیند.
- آپلود پایگاه دانش فعلاً فقط `md`/`txt` را پشتیبانی می‌کند (نه PDF) تا این پروژه بدون هیچ وابستگی npm بماند.
- صف «پیشنهاد خودکار دانش» (self-growing knowledge) که در business-generator از حافظه‌ی چند-turn چت PO استفاده می‌کرد اینجا نیست — چون این سرویس تک‌مرحله‌ای (فقط دیف → ریویو) است و معادل آن مکالمه‌ای وجود ندارد؛ افزودن استاندارد جدید همیشه دستی و از پنل `/admin` است.
